# Module 08: Next.js Full-Stack Development

## Outcome

Next.js App Router. Complete each daily lesson, then submit the module checkpoint with a README, evidence of testing, and reflection.

| Day | Lesson | Focus |
| ---: | --- | --- |
| 071 | [React versus Next.js](day-071/) | framework responsibilities, rendering, routing, and App Router setup |
| 072 | [App Router structure](day-072/) | app directory, pages, layouts, route groups, and colocated files |
| 073 | [Server and Client Components](day-073/) | server-first rendering, client boundaries, serialization, and interactivity |
| 074 | [Routing and dynamic segments](day-074/) | links, params, search params, dynamic routes, and notFound |
| 075 | [Data fetching and caching](day-075/) | server fetching, cache behaviour, revalidation, and request failure |
| 076 | [Route Handlers and API design](day-076/) | HTTP methods, validation, responses, and server-only secrets |
| 077 | [Server Actions and mutations](day-077/) | forms, server actions, validation, optimistic UI, and mutation safety |
| 078 | [Loading, errors, and resilience](day-078/) | loading.tsx, error.tsx, retry, not-found states, and graceful failure |
| 079 | [Metadata, fonts, and images](day-079/) | Metadata API, Open Graph, next/font, next/image, and accessibility |
| 080 | [Deployment and Next.js checkpoint](day-080/) | environment variables, builds, observability, and performance budgets |

## Module checkpoint

Integrate the final three days into a small, accessible Community Learning Hub milestone. Explain the user problem, decisions, test evidence, and an offline or low-resource consideration.
