# Module 06: TypeScript and Professional JavaScript Engineering

## Outcome

TypeScript. Complete each daily lesson, then submit the module checkpoint with a README, evidence of testing, and reflection.

| Day | Lesson | Focus |
| ---: | --- | --- |
| 051 | [Why TypeScript?](day-051/) | static checking, compilation, tsconfig, and gradual adoption |
| 052 | [Primitive types, arrays, tuples, and literals](day-052/) | annotations, inference, readonly data, tuples, and literal unions |
| 053 | [Objects, interfaces, and type aliases](day-053/) | structural typing, optional properties, interfaces, and aliases |
| 054 | [Function types and reusable contracts](day-054/) | parameter and return types, callbacks, overload alternatives, and void |
| 055 | [Union and intersection types](day-055/) | discriminated unions, intersections, and exhaustive handling |
| 056 | [Generics](day-056/) | type parameters, constraints, reusable data containers, and inference |
| 057 | [Narrowing and type guards](day-057/) | typeof, in, instanceof, predicates, and runtime validation |
| 058 | [Utility types and enums alternatives](day-058/) | Partial, Pick, Omit, Record, satisfies, and string unions |
| 059 | [Async and API response typing](day-059/) | Promise types, unknown, decoding, validation, and error contracts |
| 060 | [Modules, testing, and TypeScript checkpoint](day-060/) | project boundaries, linting, tests, and maintainable organization |

## Module checkpoint

Integrate the final three days into a small, accessible Community Learning Hub milestone. Explain the user problem, decisions, test evidence, and an offline or low-resource consideration.
