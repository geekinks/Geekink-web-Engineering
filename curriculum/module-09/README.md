# Module 09: Backend-as-a-Service and Data Engineering

## Outcome

BaaS and data. Complete each daily lesson, then submit the module checkpoint with a README, evidence of testing, and reflection.

| Day | Lesson | Focus |
| ---: | --- | --- |
| 081 | [Backend fundamentals before BaaS](day-081/) | HTTP APIs, validation, authentication, authorization, and trust boundaries |
| 082 | [Relational data and SQL](day-082/) | tables, rows, keys, joins, normalization, constraints, and transactions |
| 083 | [PostgreSQL design and indexes](day-083/) | relationships, query plans, indexes, migrations, and data integrity |
| 084 | [Supabase architecture](day-084/) | Postgres, Auth, Storage, Realtime, CLI, migrations, and client boundaries |
| 085 | [Supabase Auth and Row Level Security](day-085/) | identity, sessions, RLS policies, ownership checks, and service-role safety |
| 086 | [Supabase data, storage, realtime, and Edge Functions](day-086/) | CRUD, buckets, subscriptions, server functions, and secure validation |
| 087 | [Firebase architecture and Authentication](day-087/) | Firebase SDK, Auth providers, client-server limits, and Emulator Suite |
| 088 | [Firestore, Realtime Database, and data models](day-088/) | documents, collections, denormalization, queries, listeners, and offline cache |
| 089 | [Firebase Storage, Functions, and Security Rules](day-089/) | Storage, callable/HTTP functions, rules, validation, and least privilege |
| 090 | [Supabase versus Firebase integration lab](day-090/) | SQL versus documents, security, cost, realtime, offline behaviour, and lock-in |

## Module checkpoint

Integrate the final three days into a small, accessible Community Learning Hub milestone. Explain the user problem, decisions, test evidence, and an offline or low-resource consideration.
