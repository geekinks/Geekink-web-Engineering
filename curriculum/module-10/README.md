# Module 10: Production Web Engineering and Capstone

## Outcome

Production and capstone. Complete each daily lesson, then submit the module checkpoint with a README, evidence of testing, and reflection.

| Day | Lesson | Focus |
| ---: | --- | --- |
| 091 | [Full-stack architecture and capstone planning](day-091/) | requirements, boundaries, data flow, ADRs, and threat modeling |
| 092 | [Authentication and authorization](day-092/) | sessions, roles, ownership, authorization checks, and secure redirects |
| 093 | [Web security essentials](day-093/) | XSS, CSRF, injection, secrets, dependencies, headers, and input validation |
| 094 | [Frontend and component testing](day-094/) | unit tests, React Testing Library, fixtures, accessibility assertions, and test value |
| 095 | [Integration and end-to-end testing](day-095/) | contract tests, browser automation, test data, and failure paths |
| 096 | [Web performance engineering](day-096/) | Core Web Vitals, profiling, bundle analysis, caching, images, and budgets |
| 097 | [Accessibility auditing](day-097/) | WCAG-oriented checks, keyboard journeys, semantic checks, and assistive technology |
| 098 | [SEO, deployment, and CI/CD](day-098/) | production builds, deployment previews, checks, rollback, and release notes |
| 099 | [Monitoring, documentation, and handover](day-099/) | logs, error tracking concepts, runbooks, README quality, and maintenance |
| 100 | [Capstone presentation and engineering review](day-100/) | demo storytelling, evidence, peer review, reflection, and next steps |

## Module checkpoint

Integrate the final three days into a small, accessible Community Learning Hub milestone. Explain the user problem, decisions, test evidence, and an offline or low-resource consideration.
