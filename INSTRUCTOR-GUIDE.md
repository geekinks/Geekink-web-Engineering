# Instructor Guide

Follow the weekly Monday–Friday rhythm: explain the concept, model a small working slice, coach the practical work, support a real feature, then assess and reflect. Do not turn every session into a lecture; learners should write, test and discuss code in every class.

Start with the prior build, use local examples relevant to learners' communities, and teach tools only after the underlying concept. Review accessibility, failure paths, Git history, documentation and low-resource choices alongside visible functionality. Grade evidence, not bandwidth or device quality. See [learning methodology](docs/learning-methodology.md) and [assessment guide](ASSESSMENT-GUIDE.md).
