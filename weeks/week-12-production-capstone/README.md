# Week 12: Production Web Engineering and Capstone

**Outcome:** By Friday, students can deliver **Production-ready capstone: GeekInk Learning Platform or another local problem** and explain the engineering decisions behind it.

Monday to Friday are structured learning sessions. Saturday is optional revision, project completion or mentorship; Sunday is rest and preparation.

| Session | Topic | Key concepts |
| --- | --- | --- |
| Monday | [Capstone discovery and architecture](monday.md) | problem statement; PRD; SRS; personas; journey; wireframes; architecture; database design |
| Tuesday | [Secure implementation and testing](tuesday.md) | authorization; input validation; secrets; unit/integration tests; error handling |
| Wednesday | [Offline-first production hardening](wednesday.md) | PWA; service worker; Cache API; IndexedDB; queued submissions; retry; sync; conflict handling |
| Thursday | [Quality, deployment and documentation](thursday.md) | performance; accessibility; SEO; responsive testing; Vercel; production BaaS configuration |
| Friday | [Capstone presentation and engineering review](friday.md) | demo; peer review; evidence; maintenance; open source; reflection |

## Weekly deliverables

- A GitHub repository with small commits and a clear README.
- The week's practical project, including normal and failure-path evidence.
- A Friday reflection and one peer-review contribution.

## Offline-first thread

Each week considers a realistic constraint: limited data, interrupted electricity, modest hardware, unreliable requests, locally saved work, or safe synchronization. See [resources.md](resources.md) and the programme [offline-first guide](../../docs/offline-first-web-engineering.md).

## Assessment

Use the [weekly assessment template](../../assessments/weekly-assessments/template.md). The mini-project is assessed against functionality, clarity, accessibility, resilience and documentation.
