# Week 11: Backend-as-a-Service with Firebase

**Outcome:** By Friday, students can deliver **Firebase-powered collaborative application** and explain the engineering decisions behind it.

Monday to Friday are structured learning sessions. Saturday is optional revision, project completion or mentorship; Sunday is rest and preparation.

| Session | Topic | Key concepts |
| --- | --- | --- |
| Monday | [Firebase architecture and local development](monday.md) | Firebase services; SDK; project setup; Authentication; Emulator Suite |
| Tuesday | [Firestore and Realtime Database](tuesday.md) | documents; collections; denormalization; queries; listeners; RTDB comparison |
| Wednesday | [Storage, Functions and Security Rules](wednesday.md) | Firebase Storage; Cloud Functions; rules; least privilege; test rules |
| Thursday | [Collaboration, offline and hosting](thursday.md) | offline persistence; synchronization; conflicts; Hosting; graceful degradation |
| Friday | [Firebase versus Supabase decision lab](friday.md) | SQL vs documents; realtime; offline; security; cost; lock-in; use cases |

## Weekly deliverables

- A GitHub repository with small commits and a clear README.
- The week's practical project, including normal and failure-path evidence.
- A Friday reflection and one peer-review contribution.

## Offline-first thread

Each week considers a realistic constraint: limited data, interrupted electricity, modest hardware, unreliable requests, locally saved work, or safe synchronization. See [resources.md](resources.md) and the programme [offline-first guide](../../docs/offline-first-web-engineering.md).

## Assessment

Use the [weekly assessment template](../../assessments/weekly-assessments/template.md). The mini-project is assessed against functionality, clarity, accessibility, resilience and documentation.
